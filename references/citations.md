# 参考文献：检索、筛选、核对

写作模式才用。**只排版时**只看最后一节“只排版时核对原文的文献”：原稿的参考文献一个字不改，篇数不够也不补。

条目的写法和排版**不变**：按第 8 节的模板写法写；字体字号、编号、分页由脚本按模板处理。

## 1. 先看自己能不能检索

| 情况 | 怎么做 |
|---|---|
| 有联网搜索、网页读取等工具 | 按第 2–9 节做 |
| 没有这些工具 | 只用用户给的文献。用户也没给 → `references` 写 `[]`，回复里告诉用户还需要几篇、请用户提供。**绝不凭记忆写条目** |

## 2. 去哪里找（参考顺序）

1. 用户提供的文献（本地 PDF、Zotero 库、导师指定书目）。
2. 学术数据库：
   - 中文：知网 > 万方 > 维普。
   - 英文：Semantic Scholar / OpenAlex / DBLP > Crossref > IEEE Xplore / ACM DL > Google Scholar（补漏用）。
   - arXiv：只作补充；有正式发表版本时换成正式版。
3. 权威一手来源：国家标准（GB/T）、ISO、RFC、官方技术文档、政府和机构报告。
4. 普通网页搜索：只用来找线索，必须找到第 1–3 类里的原文后才能引用。
5. 你的记忆：**只能用来想检索词，不能写成条目。**

网站要登录或验证码时不要绕过，换别的来源；只能在那里查到的，`refs` 会判为“无法验证”。

## 3. 一票否决（命中任意一条就不用）

- 已撤稿。
- 掠夺性期刊或来源不明的期刊。
- 作者、题目、年份、刊名和 Crossref 或知网的记录对不上。
- 没有读到原文或摘要。
- 没有 DOI、ISBN，也没有可访问的原文链接。

## 4. 相关度（对照正文里要支撑的那句话判断）

高＝直接支撑，研究对象和结论都对得上；中＝部分支撑（相关背景、类似方法）；低＝只是主题沾边，不用。

## 5. 质量参考（可选，用来在多篇候选里挑）

| 分 | 英文 / 计算机 | 中文 |
|---|---|---|
| 5 | CCF-A、中科院 1 区 | CCF 中文 A 类 |
| 4 | CCF-B、2 区 | 北大核心、CSCD、CSSCI |
| 3 | CCF-C、3 区 | 普通统计源期刊 |
| 2 | 其他正式发表 | 其他正式发表 |
| 1 | 预印本、学位论文、技术报告 | 学位论文 |

- 只是参考，不是门槛；以最新 CCF 目录和分区为准，查不到按 2 分。同分看年均引用（`refs` 会算）；近 2 年的论文不因引用少而降级。

## 6. 怎么选（参考做法）

1. 先看相关度（高 > 中），同档按质量分、再按年均引用从高到低；优先用“高相关 + 质量分 ≥ 4”。
2. 某个论点只找到中相关的文献，可以用，但记为“弱支撑”（写进回复里的清单，见第 9 节）。
3. 引言、相关工作优先综述；论点和数据优先原始研究；定义和规范优先官方标准、文档；Workshop、Poster、短文尽量不用。

## 7. 整体要求

必须做到：

- 篇数：用户说了按用户的；没说至少 6 篇（A、B 都是）。找不够就如实告诉用户还差几篇，**不凑数、不编造**。
- 同一篇不重复列。
- 正文里的具体数字（人数、百分比、倍数、金额）只能来自核对过的文献或用户资料，并在**那句话**末尾标引用序号；找不到来源就不写数字。

建议（`refs` 会统计，但不拦）：

- 近 5 年的文献占六成左右（经典奠基文献在 refs.json 里写 `"classic": true`，不计入）。
- 中英文比例按用户或学校要求，没有就不限；同一论点一般引 1–3 篇。

## 8. 用 `refs` 核对，再写进文档

把找到的每一条写进 `WORK/refs.json`（一个列表），然后运行（需要联网；用户要求的篇数不是 6 时加 `--min 篇数`）：

```bash
python -X utf8 scripts/xaufe.py refs --work "WORK"
```

```json
[
  {"text": "LECUN Y, BENGIO Y, HINTON G. Deep learning[J]. Nature, 2015, 521(7553): 436-444.",
   "doi": "10.1038/nature14539", "title": "Deep learning", "authors": ["LeCun Y", "Bengio Y", "Hinton G"],
   "year": 2015, "journal": "Nature"},
  {"text": "作者. 书名[M]. 出版地: 出版社, 年份.", "isbn": "978……", "title": "书名", "year": 2007, "classic": true},
  {"text": "用户给的条目，原样照抄", "from_user": true, "user_said": "用户的原话"}
]
```

| 字段 | 写什么 |
|---|---|
| `text` | 写进参考文献列表的那一行，写法见下面 |
| `doi` | 有就写（10. 开头）。脚本按 DOI 记录核对；没写时会按题目和第一作者去 Crossref 找，找到了也按记录核对 |
| `isbn` | 书没有 DOI 时写 ISBN。脚本按 ISBN 记录核对 |
| `title` `authors` `year` `journal` | 原文页面上的题目、作者（按顺序，至少前三位）、年份、刊名或会议名。有 DOI 记录时**每位作者**都和记录逐一比对 |
| `url` | 既没有 DOI 也没有 ISBN 时必须写：这篇文献**本身**的页面链接（期刊文章页、出版社书目页、学位论文库详情页），搜索结果页不算。脚本会打开它：题目、第一作者、年份都要在页面上；只有题目算“信息不一致”，找不到题目或链接失效就排除；网站拒绝自动访问（知网等常见）判为无法验证 |
| `supports` `relevance` | 这篇文献支撑正文里哪个论点、相关度（`"高"` 或 `"中"`）。会出现在给用户的清单里 |
| `quote` | 支撑那个论点的**原文原句**（照抄，不是概括），正文引的数字要在里面。自己找的文献必须写。脚本到摘要或链接页面里找它；对不上的列进 `REF_SUPPORT_UNCONFIRMED`，要逐条核对 |
| `classic` | 经典奠基文献写 `true`，不计入近 5 年比例 |
| `from_user` `user_said` | 用户给的文献：`from_user` 写 `true`，`user_said` 写用户的原话（原稿里有的可不写）。照样核对，只报告 |

`refs` 对每条给两个独立结论，**文献存在不等于引用正确**：

| 真实性（status） | 意思 | 怎么办 |
|---|---|---|
| 已验证 | 和公开记录（DOI/ISBN/原文页面）对得上 | 可以用 |
| 信息不一致 | 是同一篇，但作者、年份、刊名等有字段对不上；或者 `text`（印在论文里的那一行）里的题目、作者、年份、刊名、DOI 和核对过的字段不一致 | 确认后按提示改字段和 `text`，再运行 refs；不改不能用 |
| 无法验证 | 网站拒绝自动访问、链接页面只是提到它、记录只有拼音或外文、书目库里查不到这本书 | 写作时先问用户是否接受，同意后 job.json 写 `"accept_unverified_refs": true`，否则 `run` 拦下；清单写明原因 |
| 无法验证（连不上核对服务） | 没网或核对服务连不上，什么都没核对 | 联网后重新 `refs`；没法联网同上，先问用户 |
| 排除 | 不存在、已撤稿、DOI 是另一篇、链接失效 | 从 refs.json 删掉另找。**不要改成查到的那篇** |
| 用户提供 | 用户给的，核对结果只报告 | 可以用，清单写明“你提供的”和核对结果；原稿里没有又没写 `user_said` 的，`run` 拦下 |

| 观点支撑（support） | 意思 |
|---|---|
| 摘录已在原文中找到 | `quote` 出现在摘要或链接页面里 |
| 摘录在能读到的原文里没找到 | 可能来自全文；确认是原句，不是概括 |
| 取不到原文，未能对照 / 没有提供原文摘录 | 只有你的自述，清单会如实标出 |

**条目写法照模板原样**（B 版参考文献模板的示例），不要改成别的格式：

- 专著：`作者. 书名[M]. 出版地: 出版社, 年份.`
- 期刊：`作者. 题名[J]. 刊名, 年份, 卷(期): 起止页码.`
- 论文集里的文章：`作者. 题名[A]. 编者. 论文集名[C]. 出版地: 出版社, 年份. 起止页码.`
- 报纸：`作者. 题名[N]. 报纸名, 出版日期(版次).`
- 标准：`标准编号, 标准名称[S].`
- 网上文献：`作者. 题名[EB/OL]. 网址, 发表日期/引用日期.`

写进 content.json：
- `references` 按正文**第一次引用的顺序**排，每条用 refs.json 里的 `text`；序号不用自己写，脚本会加。
- 正文引用处加上标序号，例如 `"runs": [{"text": "深度学习已广泛用于图像识别"}, {"text": "[1]", "superscript": true}, {"text": "。"}]`。

`run` 会核对：content.json 的每条参考文献都在 refs 的可用结果里（按 `text` 比对，所以要原样复制）；正文的 `[n]` 都指向存在的条目；每条文献都被引用过；编号按第一次引用的顺序。

## 9. 回复里附核实清单

Word 里不加“无法验证”“弱支撑”这类标记。`finish` 会按 refs 的结果生成一张清单（序号、文献、真实性、支撑的论点、观点支撑，弱支撑会标出，篇数不够会写还差几篇），原样附在给用户的回复里。

## 只排版时核对原文的文献（只报告）

用户要求核对、或原文文献看着可疑时：`refs --work "WORK" --from-document` 按文档里的条目生成 refs.json（`text` 是原文，其他字段是猜的）再核对。字段猜错就对照原文改字段（不改 `text`）再 `refs`。不删改原文；`finish` 给出核对结果表，原样附在回复里，由用户决定改不改。
